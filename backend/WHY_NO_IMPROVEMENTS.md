## Проблема
CAD Solver работает корректно (тесты проходят, ортогонализация применяется),
но пользователь не видит улучшений в реальных чертежах.

## Причина
CAD Solver (Module 3) - это только ТРЕТИЙ модуль из четырёх. Он улучшает уже
извлечённую геометрию, но не может исправить плохое извлечение.

Текущий пайплайн:
1. OpenCV binarization (работает)
2. cv2.HoughLinesP (ПРОБЛЕМА: фрагментирует линии на 50+ сегментов)
3. CAD Solver (работает, но получает фрагментированный вход)

## Что происходит сейчас

### Пример: Штриховая линия
**Без CAD Solver:**
- HoughLinesP находит: 50 отдельных сегментов
- Каждый сегмент: немного не по оси (89.5° вместо 90°)

**С CAD Solver:**
- Получает те же 50 сегментов
- Выравнивает каждый по оси (89.5° → 90°)
- Результат: 50 идеально вертикальных сегментов (но всё ещё фрагментировано!)

## Почему так?

CAD Solver работает с polylines, которые уже извлечены. Он:
✅ Выравнивает линии по осям (89° → 90°)
✅ Привязывает вершины к пересечениям
✅ Вычисляет точные пересечения

Но он НЕ может:
❌ Объединить 50 фрагментов в одну линию
❌ Отличить толстые контурные линии от тонких проекционных
❌ Восстановить штриховые линии из фрагментов

## Решение

Нужны модули 1 и 2:

### Module 1: ML Semantic Segmentation (Недели 4-5)
- Нейросеть различает типы линий:
  * Толстые контурные линии
  * Тонкие проекционные линии
  * Штриховые линии (как НЕПРЕРЫВНЫЕ маски)
  * Текст
- Выход: 5 масок вместо одной бинарной картинки

### Module 2: Multi-Pass Vectorization (Недели 6-7)
- Скелетизация + граф вместо HoughLinesP
- 5 параллельных проходов с разными параметрами
- AI-судья выбирает лучший результат по IoU
- Результат: ОДНА полилиния вместо 50 фрагментов

### Module 3: CAD Solver (ГОТОВ)
- Получает качественные полилинии из Module 2
- Применяет геометрические ограничения
- Результат: CAD-ready геометрия
